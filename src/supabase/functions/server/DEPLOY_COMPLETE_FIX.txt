PROBLEM IDENTIFIED:
----------------
The graduated_students table contained MIXED data types in the graduation_class field:
- Some records: UUID format (e.g., "0ebd4592-0ebe-426d-943f-d0f9acab38ec") ✅
- Some records: Plain text class names (e.g., "SS3") ⚠️

When the code tried to query the classes table using .in("id", classIds), it failed with:
❌ Error: "invalid input syntax for type uuid: 'SS3'"

This happened because Postgres tried to match the string "SS3" against a UUID column.

ROOT CAUSE:
-----------
Legacy data or manual entries in the graduated_students table had class names 
instead of class UUIDs in the graduation_class field.

SOLUTION IMPLEMENTED:
--------------------
✅ Added UUID detection function (regex-based)
✅ Pre-filter graduation_class values into two categories:
   1. Valid UUIDs → Query classes table to get names
   2. Plain text → Use directly as class names (legacy data support)
✅ Build unified class map from both sources
✅ Apply correct mapping during transformation
✅ Added comprehensive debug logging

CODE CHANGES:
-------------
1. Added isUUID() helper function
2. Split graduation_class values before querying
3. Handle legacy data gracefully
4. Enhanced error logging
5. Backward compatible with all existing data

EXPECTED RESULT:

✅ Students with UUID graduation_class → Display correct class name from DB
✅ Students with text graduation_class → Display the text as-is
✅ No more "invalid input syntax for type uuid" errors
✅ All graduated students show proper class names instead of UUIDs
